# Imaging samples, anatomy assets and rebuilding

## Running SARI: no separate sample download

The repository includes the browser-ready research samples, atlas annotations and body surface under `public/data/` and `public/models/`. They are normal tracked Git files. Clone the repository, install dependencies and start the app:

```sh
git clone https://github.com/msonnendeck/sari-anatomy.git
cd sari-anatomy
npm ci
npm run dev
```

No manual download, dataset account or external sample-storage service is needed for the bundled viewer. The optional AI workflows need a separately configured Meta key and explicit approval before sharing reviewed image extracts. Imported local scans are not part of these bundled samples.

## Automated original imaging downloads

Original inputs are optional: obtain them to inspect provenance or rebuild the bundled derivatives. From the repository root, after `npm ci`:

```sh
npm run samples:download
```

Requires Node.js 22.9+ and `unzip` on PATH for the MNI archive (included with macOS and common Linux distributions). If extraction fails, the script explains where to extract the downloaded archive manually. Downloads can take time and disk space; they are not required to run the app.

For individual datasets:

```sh
npm run samples:download -- spl
npm run samples:download -- mni
npm run samples:download -- slicer
```

The script downloads to the Git-ignored `workspace/source-data/` directory:

```text
workspace/source-data/
  spl/                              # flattened pinned original atlas inputs
  mni-original.zip                  # official McGill archive
  mni/mni_icbm152_nlin_sym_09c/       # extracted original NIfTI inputs
  MRBrainTumor1.nrrd                 # checksum-addressed Slicer original
  downloads-<dataset>.json           # local download URL/hash records
```

SPL files come from the pinned source revision and are checked against the repository’s SHA-256 manifest. MRBrainTumor1 is checked against the SHA-256 in the official download URL and again by its conversion script. MNI uses the official HTTPS archive; a local hash is recorded, but no upstream checksum verification is claimed. Existing source files are reused; to fetch a fresh MNI archive, delete only `workspace/source-data/mni-original.zip` before rerunning its download command. Failed downloads use temporary `.part` files, and checksum failures are not promoted to final source files.

### Convert the original imaging inputs

Run from the repository root after downloading. These commands overwrite the corresponding bundled derivative files in `public/data/`; use a separate checkout if you want to compare against the checked-in versions.

```sh
node scripts/prepare-spl-atlas.mjs workspace/source-data/spl
node scripts/prepare-mni.mjs workspace/source-data/mni/mni_icbm152_nlin_sym_09c
node scripts/prepare-research-samples.mjs workspace/source-data
npm test
```

The research-samples conversion requires **both** the MNI archive contents and the Slicer original. The download helper establishes the exact layouts expected by the existing conversion scripts. Keep the bundled README, COPYRIGHT/COPYING and licence files alongside the outputs.

## Body surface: manual upstream download

The current helper automates the imaging sources above; it does not download BodyParts3D. The ready-to-use converted body is already bundled, so this step is optional.

1. Open the [official BodyParts3D download page](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html) and review its licence.
2. Obtain the BodyParts3D 4.0 OBJ data containing skin surface **FJ2810.obj** and extract it locally. Upstream download availability and packaging can change; the conversion takes the OBJ itself, not a ZIP file.
3. Rebuild the surface from the repo root:

```sh
node scripts/prepare-body.mjs /absolute/path/to/FJ2810.obj
```

This overwrites `public/models/body-surface.bin.gz`. Retain [ATTRIBUTION.md](../public/models/ATTRIBUTION.md), which preserves both the current official attribution and the older notice embedded in the source OBJ. No original triangles are deliberately removed or flattened by this preparation step.

## Research scope

All samples support research and educational visualization. SARI is not clinically validated and is not for diagnosis, treatment or medical advice. Source labels, human edits, AI proposals and synthetic references remain distinct.
